# New API - Zeabur 多节点集群部署指南

本文档记录了在 Zeabur 平台上部署 New API 高可用集群（跨区边缘节点）的完整策略、技术原理和操作步骤。此方案不需要借助外部的 Cloudflare 负载均衡，完全依靠 Zeabur 原生平台实现，分为**主节点环境**和**边缘子节点环境**两部分。

---

## 1. 核心架构原理

### ① 不要依赖 Zeabur 自身来"连接"跨区子节点
Zeabur 的域名管理是基于独立服务项目的。如果主节点在亚洲，子节点在美国，在平台上它们是两个互相平行的实体。不能单纯依靠界面设置就能把它们粘合在一起，而是要在**应用代码底层共享同一套状态**。

### ② 集群如何识别彼此？
主节点和所有子节点之所以能被看作一个整体，是因为我们让它们**共享下面这四样东西**：
1. `SQL_DSN`：共同连接到一个暴露在外网的 PostgreSQL 数据库主控（唯一真实落盘地）。
2. `REDIS_CONN_STRING`：共同连接到一个 Redis 缓存系统，这里用来拦截并解决并发攻击，管理高频刷单。
3. `SESSION_SECRET`：完全一致的密钥。只有钥匙一样，当用户从主站域名跳到子站域名时，系统才能认出他们的 Cookie 没失效。
4. `CRYPTO_SECRET`：完全一致的数据加密密钥。用以跨节点正常解码从数据库中读出来的用户密码本或加密过的配置单。

### ③ 防止多机"打架" (脑裂)
New API 具有定时的异步后台任务：如批量渠道测速、充值对账等。如果有五台节点平行运行并同时执行这些异步任务，不仅极大拖慢性能，还极易引发数据库死锁。
**决胜关键：**给所有的海外子节点在部署时加上 `NODE_TYPE=slave` 环境变量。这样它们会自我降级退化成**“纯粹的网络并发请求网关”**，不去抢主节点的财务核算对账活儿，安心搬砖。

## 2. 具体操作全解析（双方案）

### 方案A：使用 Nginx 的无感负载均衡 (单入口高可用)
该方案提供唯一的域名（比如 `api.zeabur.app`。用户不知道也不用管是哪个节点在接见他。我们用了一台装在主节点区域的小巧 Nginx 服务完成调度。

**优势：**对外界高度透明；当海外大模型极度吃带宽造成连接雪崩时，Nginx 自带极佳的断流缓冲处理特性。

#### 操作流程：
1. 先利用 `zeabur-cluster-master.yaml` 一键快速在亚洲区域建个完整的集群中枢（里面为你默认拉好了 Postgres, Redis, NewAPI Main，和作为网关的 Nginx）。
2. 去刚建好的 PostgreSQL 和 Redis 设置（Zeabur 的网络选项面板），把这俩都点一下**『暴露新端口』**！只有这样它们才会拥有公网 IP。
3. 记录主控暴露出的公网地址，拼接成**连接串格式**：
   - DB连接串示例：`postgresql://postgres:我的密码@34.127.x.x:30760/new-api`
   - Redis连接串示例：`redis://default:我的密码@34.127.x.x:31250`
   - 记录下你在主应用设置里的 `SESSION_SECRET` 与 `CRYPTO_SECRET`。
4. 在世界另一端的节点（如美区Zeabur），用我们另外写的极简的 `zeabur-cluster-slave.yaml` 部署小网关程序，把第 3 步得到的连接串和密钥如数填进去。
5. 这个子节点获得一个海外域名。
6. 回到最初第一步生成的那个亚洲区的小 Nginx 服务控制面板，把它需要监听的海外地址 `SLAVE_NODE_URL` 写成第 5 步那个子域名即可生效。Nginx 将会开始自动按照 3:5（主:从） 的智能比例劈开所有访问流量并往这两地撒。

### 方案B：全客户端分发制 (简单粗暴、直接明了)
如果没有部署专门的 Nginx LB 发牌员，我们可以直接暴露所有站点的各自独立域名。
这种玩法**省去了架设反向代理中间件以及处理跨区网络中断导致的死锁风险**。

#### 操作流程：
- 这方案的前四步完全可以照抄方案A，只是我们不再用什么 Nginx 去掩人耳目。
- 架构确立后，亚洲主站叫 `api-asian.xxx.com`，美国边缘分站叫 `api-usa.xxx.com`。
- 因为这两个站点底层通过上面的公网连接串死死扣在了同一个数据库账本上，所以余额和后台配置在两边都永远是一致的。
- 告知你的团队用户："国内写代码测试配 `api-asian`"，"给系统上真线、跑美国原版的 ChatGPT 请把 BaseURL 改成 `api-usa` 以获得极速的低延迟！"。

## 3. 重要答疑解惑：

**Q1：环境变量里的连接串是什么？能代替 IP 吗？**
A：能完好代替。在 Zeabur 的从节点中输入的那个类似 `postgresql://postgres:密码@34.127.x.x:30760/new-api` 就是一连完整的数据库开锁通行证，在这个句子里面早就**天生内置了这台主库计算机的绝对网络公网 IP 与它的暴露端口**。所以在从主机上不需要单独另立个表单填一次它老大的 IP，写在一句连接串里底层引擎就能自己解析清楚。

**Q2：从节点的并发数调整，是否只能在主节点设？**
A：两者在计算能力上是分开调整且平级的！一旦建好了多网关，你可以单独去美国的那个节点面板里把它拖成 `Replicas = 3`（这意味着你有三台物理虚拟服务器同时在美国接收任务并跨洋去核对数据库）。这与亚洲区的算力可以各自按需单独弹性缩放。
